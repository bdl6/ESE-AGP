# 第一阶段：跑通并讲清局部会话图

本阶段实现的是 ESE-AGP 的局部图基线，不包含完整论文模型。先读数据和测试，再读神经网络；不用一次背完所有 PyTorch API。

## 1. 先看一个样本

假设一次会话原始商品序列为 `[A, B, A, C]`。训练输入为 `[A, B, A]`，标签为 `C`。局部节点只有 A、B，两条有向边是 A→B、B→A；输入位置映射是 `[A节点, B节点, A节点]`。目标 C 不加入当前会话输入图。

如果目录映射为 A=1、B=2、C=3，模型的输出列为 `[A分数, B分数, C分数]`，交叉熵标签为 2。商品 ID 从 1 开始，类别下标从 0 开始；padding/OOV=0 从不参与推荐候选。

第一道口头练习：把 `[A, unknown, B, A]` 画成图，并指出哪些边不能建立。答案是 unknown 位置切断它两侧的相邻关系，只保留 B→A；不能补出 A→B。

## 2. 跟一次前向和反向

`collate_examples` 把几个会话拼成互不连通的局部图；相同商品在不同会话中仍有不同局部节点，但它们查询同一个可学习 embedding 表。

模型流程是：商品 ID → embedding → 两层入邻居注意力和自节点通路 → 回到原始点击位置 → 有效位置平均 → 一个线性视角及 ReLU → 与全部候选 ID embedding 点积。

`CrossEntropyLoss(logits, target)` 鼓励正确候选的分数相对其他候选更高。`backward()` 用链式法则计算各参数的梯度；`optimizer.step()` 更新 embedding、图层和预测头。优化器不更新离散商品 ID，也不修改训练标签。训练前每步需要 `zero_grad`，因为梯度默认累积。

现在能做的实验：把模型 `dim: 32` 改成 16，并将 `run_dir` 改成另一个目录；比较参数规模和日志。人工小数据上的指标变化仅用于理解，不说明真实泛化能力。

## 3. 手算一次指标

三个样本的目标分别是 A、B、unknown，Top-2 分别为 `[A,C]`、`[C,B]`、`[A,B]`。

- 全样本 HR@2 = 2/3。
- 全样本 MRR@2 = (1 + 1/2 + 0)/3 = 1/2。
- 已知目标 HR@2 = 1，MRR@2 = 3/4，OOV 目标比例 = 1/3。

未知目标必须在全样本分母中计 miss，不能删掉后只报告更漂亮的已知子集结果。HR 关注有没有命中，MRR 还关注命中位置。

## 5. 常见深挖与回答要点

**没有登录，训练时为什么还有 user_id？**

模型预测只需要当前会话序列，不需要长期用户向量；训练数据可以来自匿名 session/cookie 标识。我们选用的 Amazon 评论记录有 user_id，用它和时间构造代理会话，但这不能被描述为真实匿名浏览日志。

**为什么目标不进入局部图，却可能进入训练全局图？**

局部图描述当前可见前缀，放入目标会直接泄漏答案。后续全局图描述整个训练期的历史转移，可以使用训练样本完整序列；验证、测试交互不能加入全局训练图。两张图承担的角色不同。

**图模型会丢顺序吗？**

有向相邻边保留一部分转移关系，但合并重复节点和平均池化无法完整保留每次出现的位置、绝对顺序和时间间隔。这是设计局限，可以用位置编码或序列编码器作为后续对照，不能声称图结构保存了全部序列信息。

**为什么同一个 A 既合并节点，又在池化时算两次？**

合并节点是为了共享该会话内同一物品的表示；按位置读出是为了让重复行为的次数影响会话表示。只平均唯一节点会改变原本的读出定义。

**loss 下降就能证明模型有效吗？**

小数据过拟合说明训练与梯度链路基本可工作；模型是否有用还要看真实时间切分上的验证/测试指标、同口径基线和消融。小候选集 HR@20 接近 1 尤其不能证明模型有竞争力。

**为什么先写基线？**

热门策略验证数据和评估链路，转移策略检验最近一次行为是否已有很强信号；复杂模型应在相同目录、切分和评估协议下比较，才能判断额外模块的收益。

## 6. 本阶段学习验收

- 手工写出一个输入前缀、目标及候选类别下标。
- 能解释局部图方向、OOV 断边、重复点击池化和批内图隔离。
- 找到训练代码中 zero_grad、forward、loss、backward、step 五个位置。
- 手算 HR/MRR，并说清全样本与已知目标子集的区别。
- 运行一次测试和训练，指出产物目录以及验证集选择 checkpoint 的位置。

本阶段之后：接入 Amazon 原始数据与商品属性，记录缺失/过滤/OOV 数量及预处理吞吐；再增加行为全局图与实体流程。
