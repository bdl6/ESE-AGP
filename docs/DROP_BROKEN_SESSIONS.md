# 低频商品导致断裂时丢弃整个会话（2026-11-01）

这是用户明确指定的复现规则，不能宣称论文已经明确规定采用此策略。

## 执行规则

固定最初24小时window_id，在截断和随机划分前循环：用户交互>=3、会话长度>=2、计算商品交互频次。只要一个会话任意位置含频次<5的商品，就丢弃该会话全部事件。随后继续检查用户、会话和商品，直到本轮没有任何事件删除。

例如`[A,X,B,C]`中X为低频商品，结果是丢弃整段，而不是`[A,B,C]`，不由本会话新建A→B转移。首尾出现低频商品也按同样规则丢弃，不保留残段、不拆分会话。同一用户其他完整会话可保留，若该用户总频次随后不足3，则继续剔除。

收敛后SQL独立校验保留会话的事件条数等于低频过滤前events中的完整会话，且用户>=3、商品>=5、会话>=2。固定源集合且只删除原有记录，因此此检查能确认没有会话内删点拼接。

前置元数据清洗仍保持原规则：价格/类别无效交互在切窗前删除。这里的会话完整性针对该清洗之后、低频过滤之前的会话；本次没有扩展成“任意原始记录清洗都丢整段”的额外规则。

最后一项作为预测目标，之前最多20次作为输入；截断仅保留连续尾部，不产生跨过滤断点的相邻边。保持随机9:1，保留重复交互，不按训练未见删除商品。
