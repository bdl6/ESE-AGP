# 100商品优化计时（2026-11-01）

独立实验，不改变现有CLI、串行模块和旧结果。保留原五步流程、四套提示词、描述审查、3轮补充、4096输出token和失败隔离。不同商品/实体/候选对并发，同一块多轮和同一描述生成→审查保持顺序。

## 实现

- workflow_optimized.py：有界线程池，4并发，固定顺序归并。预算预留与usage持锁；相同缓存键互斥；事件日志持锁；每线程独立HTTP适配器。
- optimized_candidates.py：同类型词项/字符三元组/缩写索引召回；相似度阈值0.65，每实体top8非同名候选；同名组星形连接保留连通性。所有候选仍交给LLM判断，不自动同名合并。此策略非穷尽，须评估召回。
- benchmark_optimized.py：同100个商品ID、相同规范文本和数据指纹；冷应用缓存，模型已加载，服务前缀缓存不清理。短请求已验证2/4并发可用，但不用于完整流程性能外推。

## 基准与质量限制

旧串行完整实验58808.52秒，99成功1失败；联合抽取约84分钟。新实验分别输出extraction_timing.json和完整timing_report.json。HTTP时延重叠，不可相加当墙钟时间。比较脚本记录同一定义下联合抽取区间速度及总速度。

在旧实体上离线审计，新候选786对，旧4640对；旧165次获准判断中94对直接保留，164对在新候选图中连通。星形边减少同名重复比较，但候选连通不保证LLM接受路径。旧LLM判断不是人工真值；最终记录共享实体上合并分组一致性，不能只凭速度或连通率声称质量相同。候选数改变、服务负载未控制，联合优化不是纯并发因果实验。
