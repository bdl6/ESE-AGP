# 论文协议：迭代过滤到收敛

实现：`src/ese_agp/data/amazon.py`中的`iterative_session_filter()`。仅论文协议切换为此规则，旧实验数据不覆盖。

## 顺序与收敛条件

先用parent_asin关联元数据并删除价格/类别无效交互，初始过滤用户后，以首次有效交互为锚点固定24小时window_id。随后循环：

1. 当前全部会话中，删除交互次数不足3的用户对应交互。
2. 删除当前长度不足2的会话。
3. 统计当前有效会话中的商品交互频次，删除出现不足5次的商品对应交互。
4. 再删除长度不足2的会话。
5. 本轮没有删除任何交互才停止，否则回到第1步。

整个过程只删除记录，不重新切窗、不合并会话、不添加记录。因此记录数不变意味着交互集合不变。停止后另行SQL验证全部用户>=3、商品>=5、会话>=2。频次按交互次数统计，不是去重用户数；重复事件仍保留。

## 截断与划分

收敛约束在截断前的完整会话上成立。随后会话级随机9:1划分，最后一次作为目标，目标之前最近20次作为输入。截断可能降低最终模型样本的商品/用户频次，因此最终样本不足阈值不等于完整会话未收敛。
保留目录包括训练和测试商品，不添加“训练未见商品就删除”的规则。类别/价格统计与既有paper协议一致，拟合全体保留目录。
